## 4. 需要修正的元数据与验证表述

1. **运行时间错误。** run_manifest开始/结束相差11微秒，但wall_seconds=86.7334秒；源码在结尾连续调用两次now生成这两个时间。未来版本须在真正开始时记录，既有记录按日志证据修订，不反推一个时间冒充实测。此错误不直接改变费用。
2. **训练行核验覆盖不足。** 23号perturbation_checks里的training_rows_equal仅比较训练日数、行数和分支，不比较行键、特征矩阵、标签或分箱。检查确实重训目标日模型，但历史发布预测与实际日初态复用干净基线，没有从共同起点重建全部前缀。应写清是“目标日重训＋冻结历史档案/初态的条件检查”，不能称已完整验证所有前缀。独立审计需补矩阵/标签/行键及前缀证据；本次代码阅读未发现足以直接证明数值结果泄漏的事实。
3. **半日前缀范围不足。** 只检查候选P1的两个α、两种扰动，共4例，不是四组各自都检验；state[:72]仅覆盖状态边界0—71，漏掉slot71结束后的state[72]。费用未显式列入比较。应补全四组、state[:73]及费用，或准确限缩现有检查声明。
4. **独立重训措辞。** control_refit_check和sampled_retraining_checks复用实验自身fit_day/day_features；这是重跑一致性及模型重载自检，不是独立重建算法的审计。后者docstring称“两套特征”，实际只调用support12；原8列有另一项全年控制重训，不能混称同一项覆盖两套。24号须按独立路径抽样构造特征并重训，MILP抽样独立证据也尚待补齐。
5. **1月1日窗口元数据未初始化。** support_windows.csv及候选发布档案该日记录s=0/e=0/v=0，长度1/6小时、中点1/12小时；约定应为s=0/e=143/v=0。源码build_pv_forecast从k=1开始，留下数组零值。1月1日无有效预测且不入训练/误差档案，本次未见其影响正式期费用；应修元数据，不把它当真实短窗口。
6. **统计范围和文件格式。** 被归零21408段/2.496083 kWh是全年365日；正式评价期为19705段，报告须分开。JSON中的无值字段使用NaN不属于严格JSON，应改null并保留状态；报告无样本子集显示NA。复现命令宜统一写conda run -n math_modeling，不必把已有同环境绝对解释器误说为换环境。

这些问题应在独立审计与修订中逐项落实；不能因费用账本通过便宣告整套实验验证完毕。修复保存为可追溯版本，不覆盖旧签名来源。
