# B题 管道最优铺设问题 — 建模报告与算法规格书

## 问题重述与数学建模

### 问题背景

某地区有180个需要集中供水的地点，分布在约50×55公里的区域内。在A处（坐标(26,31)）建立中心供水站后，需要从180个地点中选出若干作为一级供水站，其余为二级供水站，通过两级管道网络将水从中心站输送达每一个供水点。问题的核心决策是：选哪些点做一级站、管道如何连接，才能使总铺设费用最小。

### 符号定义

| 符号 | 含义 |
|------|------|
| $V = \{0, 1, 2, \ldots, 180\}$ | 全部节点集合，0为中心站A |
| $(x_i, y_i)$ | 节点 $i$ 的坐标（公里） |
| $d_{ij} = \sqrt{(x_i - x_j)^2 + (y_i - y_j)^2}$ | 节点 $i, j$ 间欧氏距离 |
| $S \subseteq V \setminus \{0\}$ | 一级供水站集合（决策变量） |
| $T = V \setminus \{0\} \setminus S$ | 二级供水站集合 |
| $E_I$ | I型管道边集（连接A↔一级站、一级站↔一级站） |
| $E_{II}$ | II型管道边集（连接一级站↔二级站、二级站↔二级站） |
| $L_I = \sum_{(i,j) \in E_I} d_{ij}$ | I型管道总长度（公里） |
| $L_{II} = \sum_{(i,j) \in E_{II}} d_{ij}$ | II型管道总长度（公里） |
| $c_I = 1291$ 元/米 $= 1291000$ 元/公里 | I型管道单位成本（材料571+铺设720） |
| $c_{II} = 445$ 元/米 $= 445000$ 元/公里 | II型管道单位成本（材料235+铺设210） |

### 目标函数

$$\min \; C_{total} = c_I \cdot L_I + c_{II} \cdot L_{II} = 1291000 \cdot L_I + 445000 \cdot L_{II}$$

### 约束条件

**C1 连通性约束**：每个二级站必须通过II型管道路径连接到某个一级站；每个一级站必须通过I型管道路径连接到中心站A。即整个管网必须是一棵以A为根的连通树（或等价地，I型子网连通所有一级站与A，每个II型子网连通其簇内所有二级站与对应一级站）。

**C2 层级约束**：中心站A只能出现在I型管道网络中，不能直连二级站。

**C3 节点出发约束**：管道只能从供水站位置节点出发，不允许在管道中间任意点分支。这意味着管网必须是图上的树/森林结构，不能引入Steiner点。

**C4 容量约束（30公里上限）**：对每个一级站 $s \in S$，以其为根的II型管道子树总边长不超过30公里：

$$\forall s \in S: \sum_{(i,j) \in E_{II}^{(s)}} d_{ij} \le 30 \text{ (公里)}$$

**C5 节点归属唯一性**：每个二级站恰好属于一个一级站的管辖簇。

### 问题复杂度分析与求解策略选择

本问题本质上是**带容量约束的两级设施选址问题（Capacitated Two-Level Facility Location Problem）**与**网络设计问题**的组合。选址部分为NP-Hard——一级站选取方案数为 $2^{180}-1$，穷举不可行；网络设计部分在给定选址后等价于带约束的最小生成树问题，可多项式时间求解。

因此，我们采用"分而治之"的策略：先通过空间聚类确定簇的划分（解决"谁归谁管"），再在每个簇内选址（解决"谁是头"），然后用图论算法生成最优管网（解决"怎么连"），最后用模拟退火进行全局优化（解决"能不能更好"）。这一策略将原本不可解的组合爆炸问题分解为若干可在合理时间内求解的子问题，同时通过迭代优化保证解的质量。

## 第一步：数据预处理与全连接距离矩阵计算

### 求解思路（自然语言描述）

在着手解决选址和管网设计之前，首先需要建立一个完整的"空间关系底图"。181个节点（1个中心站+180个供水点）两两之间的欧氏距离构成了后续所有决策的基础——无论是判断两个点是否适合归入同一个簇，还是计算管道的实际长度，都依赖于这张距离表。

具体而言，我们读取表1中所有节点的坐标数据，计算任意两点间的直线距离，形成一个181×181的对称距离矩阵。这个矩阵是对完全图 $K_{181}$ 的边权描述，共包含 $\binom{181}{2}=16290$ 条潜在连接。

考虑到后续聚类和MST算法的效率，我们进一步利用Delaunay三角剖分对候选边进行筛选。Delaunay三角剖分是计算几何中的经典工具，它有一个重要性质：欧氏空间中任意点集的最小生成树一定是其Delaunay图的子图。这意味着，即使我们丢弃大量"绕远"的边，也不会丢失最优管网所需的任何边。剖分后边数从16290条降至约537条，大幅缩减了搜索空间。当然，对于181个节点的规模，即使使用完全图计算量也完全可接受，Delaunay筛选作为可选优化存在。

### 算法与实现规格

**数据结构**：

```python
import numpy as np
from scipy.spatial.distance import cdist

# 节点坐标数组，shape = (181, 2)，索引0为中心站A
coords = np.array([
    [26, 31],  # 节点0: 中心站A
    [5, 33],   # 节点1: P1
    [8, 9],    # 节点2: P2
    # ... 共181行，见附录
], dtype=np.float64)

# 全连接距离矩阵
dist_matrix = cdist(coords, coords, metric='euclidean')  # shape (181, 181)
```

**Delaunay三角剖分（可选）**：

```python
from scipy.spatial import Delaunay

tri = Delaunay(coords)
edges_delaunay = set()
for simplex in tri.simplices:
    for i in range(3):
        for j in range(i+1, 3):
            a, b = simplex[i], simplex[j]
            edges_delaunay.add((min(a,b), max(a,b)))
```

### 输出规格

| 输出项 | 格式 | 说明 |
|--------|------|------|
| `coords` | np.ndarray (181, 2) | 节点坐标 |
| `dist_matrix` | np.ndarray (181, 181) | 对称距离矩阵，对角线为0 |
| `edges_delaunay` | set of tuple | （可选）候选边集 |

## 第二步：基于"30公里上限"的空间受限聚类

### 求解思路（自然语言描述）

这一步是整个模型的核心难点，也是决定方案优劣的关键环节。

我们的目标是将180个二级供水点划分为若干个"簇"（Cluster），每个簇将来由一个一级供水站管辖。划分的核心约束来自题目中的30公里上限：从一级站出发铺设的II型管道总里程不能超过30公里。由于簇内管网采用最小生成树（MST）结构（这是连接给定节点集的最短网络），因此约束等价于"每个簇的MST总长度不超过30公里"。

为什么不能使用普通的K-Means聚类？原因有二：第一，K-Means以"到质心的距离平方和"为目标，无法直接控制MST长度；第二，K-Means生成的簇形状倾向于圆形，而管道网络是树状的，链状或狭长形的簇反而更适合。

我们选择**凝聚层次聚类（Agglomerative Clustering）**作为基础框架，并嵌入MST长度校验作为合并准则。算法的逻辑非常直观：初始时每个节点自成一簇（180个单点簇），然后反复执行"找到距离最近的两个簇→尝试合并→检查合并后MST是否超30公里→不超就合并，超了就拒绝并尝试下一对"。这个过程持续进行，直到没有任何一对簇可以在30公里约束下合并为止。

这里有一个重要的设计选择：簇间距离采用**单链接（Single Linkage）**准则，即两个簇之间的距离定义为它们之间最近的两个节点的距离。选择单链接的理由是它倾向于生成链状簇，与管道网络的树状拓扑天然匹配，且更容易满足MST长度约束（链状结构的MST长度增长较慢）。

关于初始簇数量的估算：180个点分布在约50×55公里范围内，全局MST总长估计在200-300公里量级。以30公里为上限，至少需要 $\lceil 200/30 \rceil \approx 7$ 个簇。实际聚类结果预计产生8-15个簇，具体取决于点的空间分布密度。

### 算法与实现规格

```
ALGORITHM: ConstrainedAgglomerativeClustering
INPUT:  node_set = {1, 2, ..., 180}, dist_matrix, max_mst_length = 30.0
OUTPUT: clusters = [C_1, C_2, ..., C_K]，每个簇的MST长度 ≤ 30

1. 初始化：每个节点为一个独立簇
   clusters = [{1}, {2}, ..., {180}]
   cluster_mst[i] = 0.0  // 单节点MST长度为0

2. 计算所有簇对之间的距离（单链接准则）：
   FOR each pair (C_a, C_b):
       inter_dist(C_a, C_b) = min{dist_matrix[i][j] : i ∈ C_a, j ∈ C_b}

3. WHILE 存在可合并的簇对:
   a. 找到距离最近的簇对 (C_a*, C_b*) = argmin inter_dist(C_a, C_b)
   
   b. 尝试合并：C_trial = C_a* ∪ C_b*
   
   c. 计算 C_trial 的MST长度：
      mst_trial = Prim_MST(C_trial, dist_matrix)
      L_trial = sum of edge weights in mst_trial
   
   d. IF L_trial <= 30.0:
        执行合并：
        clusters.remove(C_a*); clusters.remove(C_b*)
        clusters.add(C_trial)
        cluster_mst[C_trial] = L_trial
        更新 inter_dist 表（新簇与其他簇的距离取min）
      ELSE:
        标记 (C_a*, C_b*) 为"不可合并"
        从候选列表中移除该对
        继续尝试下一对最近的簇
   
   e. 终止条件：所有剩余簇对均不可合并

4. RETURN clusters
```

**MST计算子程序**：

```python
def compute_mst_length(node_subset, dist_matrix):
    """
    计算给定节点子集的MST总长度（Prim算法，O(n^2)）
    返回: (总长度, 边列表)
    """
    nodes = list(node_subset)
    n = len(nodes)
    if n <= 1:
        return 0.0, []
    
    in_tree = {nodes[0]}
    mst_edges = []
    total_length = 0.0
    
    while len(in_tree) < n:
        min_edge = None
        min_dist = float('inf')
        for u in in_tree:
            for v in nodes:
                if v not in in_tree and dist_matrix[u][v] < min_dist:
                    min_dist = dist_matrix[u][v]
                    min_edge = (u, v)
        in_tree.add(min_edge[1])
        mst_edges.append(min_edge)
        total_length += min_dist
    
    return total_length, mst_edges
```

**实现注意事项**：
- 合并校验是计算瓶颈：每次合并需重新计算MST，复杂度 $O(|C|^2)$。对于180个节点逐步合并到约10-15个簇，总计算量可接受。
- 优化：维护优先队列（最小堆）存储簇对距离，避免每轮全量扫描。
- 若某节点与所有其他簇合并后MST均超30公里，该节点将独立成簇（单节点簇合法，MST=0）。

### 输出规格

| 输出项 | 格式 | 说明 |
|--------|------|------|
| `clusters` | list of set | 每个元素为一个簇的节点集合 |
| `cluster_mst_lengths` | list of float | 对应每个簇的MST总长度 |
| `cluster_mst_edges` | list of list[tuple] | 每个簇的MST边列表 |

## 第三步：确定一级供水站的最优位置

### 求解思路（自然语言描述）

经过第二步，180个供水点已被划分为若干个合法的簇，每个簇的MST长度都不超过30公里。现在需要在每个簇内部选出一个节点"升级"为一级供水站。这个选择并非随意——一级站的位置同时影响两类成本：

第一类是**簇内成本**（II型管道）。一级站是簇内管网的"根"，虽然MST的总长度与根的选择无关（无向图MST唯一），但一级站的位置决定了管道的实际走向和施工布局。选择簇的"图论中心"（到簇内所有其他节点距离之和最小的点）可以使管道分布更均匀，减少最远端供水点的管道长度。

第二类是**簇外成本**（I型管道）。一级站必须通过I型管道连接到中心站A或其他一级站。I型管道单价（1291元/米）是II型（445元/米）的近3倍，因此一级站距离A或相邻一级站越近，I型管道成本越低。

我们设计一个加权评分函数来平衡这两类成本：对簇内每个候选节点，计算其"内部距离和"与"到最近一级站/A的距离"的加权和，选评分最小的节点。权重取 $\alpha=0.6$（内部）、$\beta=0.4$（外部），反映"簇内覆盖质量略优先于外部连接成本"的设计倾向。

各簇的选址存在耦合关系——后确定的簇可以利用已确定的一级站位置来降低外部成本。因此我们按照各簇质心到A的距离从近到远排序，依次处理：先确定离A最近的簇的一级站，后续簇在计算外部成本时就能参考已有的一级站位置，从而倾向于选择靠近已有一级站的节点，最终减少I型管道总长。

选定一级站后，还需进行冗余校验：重新确认该簇的MST长度仍在30公里以内（理论上MST与根无关，此步为安全起见）。

### 算法与实现规格

```
ALGORITHM: SelectPrimaryStation
INPUT:  clusters (按质心到A距离排序), dist_matrix
OUTPUT: primary_stations (每个簇的一级站节点编号)

S_already = {}  // 已确定的一级站集合

FOR k = 1 TO K (按簇质心到A的距离从近到远):
    FOR each node v in clusters[k]:
        // 内部成本：到簇内所有其他节点的距离之和
        f_int = sum(dist_matrix[v][u] for u in clusters[k] if u != v)
        
        // 外部成本：到中心站A或到已有一级站的最近距离
        f_ext = dist_matrix[v][0]  // 到A的距离
        IF S_already is not empty:
            f_ext = min(f_ext, min(dist_matrix[v][s] for s in S_already))
        
        score[v] = 0.6 * f_int + 0.4 * f_ext
    
    primary_stations[k] = argmin score[v]
    S_already.add(primary_stations[k])

RETURN primary_stations
```

### 输出规格

| 输出项 | 格式 | 说明 |
|--------|------|------|
| `primary_stations` | list of int | 每个簇选定的一级站节点编号 |
| `S` | set of int | 一级站集合 |
| `T` | set of int | 二级站集合 = {1..180} \ S |

## 第四步：全局图论组网与总成本核算

### 求解思路（自然语言描述）

到这一步，所有节点的角色已经确定：中心站A、若干一级站、其余二级站。接下来要解决的是"怎么连"的问题——在满足所有约束的前提下，生成总成本最低的树状管网。

管网分为两个层次，分别独立求解：

**二级管网（II型管道）**：在每个簇内部，以该簇的一级站为根节点，对簇内所有节点（一级站+二级站）生成最小生成树。MST是连接给定节点集的最短网络——这是图论的经典结论（Kruskal 1956, Prim 1957）。由于题目约束C3禁止从管道中间分支，管网必须是图上的树结构，而MST恰好是所有树结构中总边权最小的那个。每个簇的MST总长已在第二步中确认不超过30公里，满足约束C4。

**一级管网（I型管道）**：提取中心站A和所有一级站，对这些节点生成全局最小生成树。这棵MST保证了从A出发可以到达每一个一级站（满足连通性约束C1），且I型管道总长度最短。由于MST覆盖所有输入节点，中心站A自然包含在内。

两层管网独立取MST的合理性在于：I型和II型管道单价不同（1291 vs 445元/米），它们的目标函数天然分离。在给定簇划分和一级站位置后，两层管网的最优结构各自独立确定，不存在耦合。

最终总成本为：

$$C_{total} = 1291000 \times L_I + 445000 \times L_{II} \quad \text{(元)}$$

### 算法与实现规格

```
ALGORITHM: GenerateSecondaryNetwork
INPUT:  clusters, primary_stations, dist_matrix
OUTPUT: E_II (II型管道边集), L_II (总长度)

E_II = []
L_II = 0.0

FOR k = 1 TO K:
    nodes_k = clusters[k]
    mst_edges_k = Prim_MST(nodes_k, dist_matrix)
    E_II.extend(mst_edges_k)
    L_II += sum(dist_matrix[u][v] for (u,v) in mst_edges_k)
    ASSERT L_II_k <= 30.0

RETURN E_II, L_II
```

```
ALGORITHM: GeneratePrimaryNetwork
INPUT:  S (一级站集合), dist_matrix
OUTPUT: E_I (I型管道边集), L_I (总长度)

nodes_I = {0} ∪ S
mst_I = Kruskal_MST(nodes_I, dist_matrix)
E_I = mst_I.edges
L_I = sum(dist_matrix[u][v] for (u,v) in E_I)

RETURN E_I, L_I
```

**成本分解输出**：

```python
cost_report = {
    "一级站数量": len(S),
    "一级站编号": sorted(S),
    "I型管道边数": len(E_I),
    "I型管道总长_km": L_I,
    "I型管道费用_元": 1291000 * L_I,
    "II型管道边数": len(E_II),
    "II型管道总长_km": L_II,
    "II型管道费用_元": 445000 * L_II,
    "总费用_元": 1291000 * L_I + 445000 * L_II,
    "各簇详情": [
        {
            "簇编号": k,
            "一级站": primary_stations[k],
            "簇内节点数": len(clusters[k]),
            "II型管道长度_km": cluster_mst_lengths[k],
            "是否满足30km约束": cluster_mst_lengths[k] <= 30.0
        }
        for k in range(K)
    ]
}
```

| 输出项 | 格式 | 说明 |
|--------|------|------|
| `E_I` | list of tuple | I型管道边列表 [(u,v), ...] |
| `E_II` | list of tuple | II型管道边列表 |
| `L_I` | float | I型管道总长（公里） |

## 第五步：算法迭代与局部搜索优化（Simulated Annealing）

### 求解思路（自然语言描述）

前四步通过"聚类→选址→组网"的流水线生成了一个初始可行解。然而，这个解的质量受限于聚类阶段的贪心策略——凝聚聚类每一步只做局部最优的合并决策，无法保证全局最优。例如，可能存在这样的情况：将某个边界节点从当前簇移到相邻簇后，虽然当前簇的MST略有增加，但相邻簇因此可以省去一条很长的边，总体成本反而下降。这类"需要暂时变差才能最终变好"的优化，贪心算法无法发现。

为此，我们引入**模拟退火算法（Simulated Annealing, SA）**进行全局搜索。SA的核心思想来源于冶金学中的退火过程：金属在高温下原子活跃，可以跳出局部能量陷阱；随着温度缓慢降低，原子逐渐稳定到全局最低能量状态。类比到优化问题：在高温阶段，算法以较大概率接受"变差"的解（跳出局部最优）；随着温度降低，接受变差解的概率逐渐趋零，算法收敛到（近似）全局最优。

**解的编码**：一个完整解由"簇划分"和"一级站选择"唯一确定——给定这两者，两层管网的MST结构是确定的，总成本可直接计算。因此搜索空间的核心变量是簇划分方案和一级站位置。

**邻域算子设计**：我们设计三类变异操作来探索解空间：

- **算子A（边界节点漂移）**：随机选一个二级站，尝试将其从当前簇移到相邻簇。这模拟了"调整管辖边界"的操作，是最细粒度的搜索。
- **算子B（一级站替换）**：在某个簇内随机换一个节点做一级站。这改变了I型管道的接入点，可能显著影响I型管道总长。
- **算子C（簇分裂与合并）**：将一个大簇拆为两个，或将两个小簇合为一个。这改变了簇的数量和宏观结构，是最大粒度的搜索。

三类算子以概率(0.5, 0.3, 0.2)随机选择，保证搜索既有频繁的精细调整，也有偶尔的结构重组。

**约束处理**：所有算子生成的邻域解必须满足30公里硬约束。若某次变异导致某个簇的MST超过30公里，直接丢弃该邻域解，不计算目标函数。这种"拒绝不可行解"策略简单有效，避免了罚函数法可能导致的搜索偏向不可行区域的问题。

**收敛与重启**：为降低对初始解的敏感性，采用多次重启策略（5-10次），每次用不同的随机种子生成不同的初始聚类，分别进行SA优化，最终取所有运行中的最优解。

### 算法与实现规格

**解的编码**：

```python
class Solution:
    clusters: list[set]          # K个簇的节点划分
    primary_stations: list[int]  # 每个簇的一级站
    E_I: list[tuple]            # I型管道边（由一级站集合唯一确定为MST）
    E_II: list[list[tuple]]     # 每个簇的II型管道边
    L_I: float                  # I型管道总长
    L_II: float                 # II型管道总长
    C_total: float              # 目标函数值
```

**算子A：边界节点漂移**：

```
ALGORITHM: Operator_NodeReassign
INPUT:  current solution X, dist_matrix
OUTPUT: neighbor solution X' (or None if infeasible)

1. 随机选择一个二级站 v ∈ T
2. 找到 v 当前所属簇 C_a
3. 找到与 v 距离最近的另一个簇 C_b（按 v 到 C_b 中最近节点的距离）
4. 尝试将 v 从 C_a 移到 C_b：
   C_a' = C_a \ {v},  C_b' = C_b ∪ {v}
5. 校验：MST(C_b') ≤ 30 （C_a'移除节点后MST只减不增，必然满足）
6. 若校验通过，重新计算两个簇的一级站和全局MST，生成新解 X'
7. 否则返回 None
```

**算子B：一级站替换**：

```
ALGORITHM: Operator_PrimarySwap
INPUT:  current solution X, dist_matrix
OUTPUT: neighbor solution X'

1. 随机选择一个簇 C_k
2. 随机选择 C_k 中另一个节点 v ≠ 当前一级站 s_k
3. 将一级站替换为 v
4. 重新计算全局I型管道MST（一级站坐标变了）
5. 簇内II型管道MST不变（MST与根无关）
6. 生成新解 X'
```

**算子C：簇分裂与合并**：

```
ALGORITHM: Operator_SplitMerge
INPUT:  current solution X, dist_matrix
OUTPUT: neighbor solution X' (or None if infeasible)

// 分裂（概率较高）
1. 随机选择节点数 ≥ 4 的簇 C_k
2. 随机选一个节点为种子，用最近邻扩展生成子簇 C_k1（大小约为原簇的1/3~1/2）
3. C_k2 = C_k \ C_k1
4. 校验两个子簇MST均 ≤ 30
5. 为每个子簇选新一级站，重新计算全局I型MST

// 合并（概率较低）
6. 随机选两个簇 C_a, C_b
7. 若 MST(C_a ∪ C_b) ≤ 30，则合并为一个簇，选新一级站
```

**模拟退火主框架**：

```
ALGORITHM: SimulatedAnnealing
INPUT:  initial_solution X_0, dist_matrix
OUTPUT: best_solution X_best

PARAMETERS:
    T_0 = 自适应估计（见下文）
    T_end = 0.01
    alpha = 0.997（降温系数）
    n_iter_per_temp = 200

1. X_current = X_0;  X_best = X_0;  T = T_0

2. WHILE T > T_end:
   FOR iter = 1 TO n_iter_per_temp:
   
     a. 按概率(0.5, 0.3, 0.2)随机选择算子A/B/C
     b. 执行算子生成 X_neighbor
     c. 若算子返回 None（约束不满足），跳过
     
     d. ΔC = C_total(X_neighbor) - C_total(X_current)
     
     e. Metropolis接受准则：
        IF ΔC < 0: 接受
        ELSE: 以概率 exp(-ΔC / T) 接受
     
     f. IF C_total(X_current) < C_total(X_best):
            X_best = X_current
   
   g. T = alpha * T

3. RETURN X_best
```

**初始温度自适应估计**：

```python
def estimate_initial_temperature(X0, dist_matrix, n_samples=100):
    """生成n_samples个随机邻域解，设T_0使初始接受率约80%"""
    deltas = []
    for _ in range(n_samples):
        X_neighbor = random_perturbation(X0, dist_matrix)
        if X_neighbor is not None:
            deltas.append(X_neighbor.C_total - X0.C_total)
    positive_deltas = [d for d in deltas if d > 0]
    if positive_deltas:
        T0 = -np.mean(positive_deltas) / np.log(0.8)
    else:
        T0 = X0.C_total * 0.05
    return T0
```

**多次重启**：

```python
best_overall = None
for restart in range(5):  # 5~10次重启
    X0 = generate_initial_solution(seed=restart)
    X_sa = simulated_annealing(X0, dist_matrix)
    if best_overall is None or X_sa.C_total < best_overall.C_total:
        best_overall = X_sa
```

**收敛判定（多重终止条件）**：
1. 温度降至 $T_{end}$ 以下。
2. 连续2000次迭代未改善最优解。
3. 总迭代次数上限50000次。

def main():
    # ===== 第一步：数据预处理 =====
    coords = load_coordinates("题目数据")
    dist_matrix = compute_distance_matrix(coords)
    
    # ===== 第二步：约束聚类 =====
    clusters, cluster_mst_info = constrained_agglomerative_clustering(
        nodes=range(1, 181), dist_matrix=dist_matrix, max_mst_length=30.0
    )
    
    # ===== 第三步：一级站选址 =====
    primary_stations = select_primary_stations(
        clusters=clusters, dist_matrix=dist_matrix, center_node=0
    )
    
    # ===== 第四步：管网生成 =====
    E_I, L_I = generate_primary_network(primary_stations, dist_matrix)
    E_II, L_II = generate_secondary_network(clusters, dist_matrix)
    C_total = 1291000 * L_I + 445000 * L_II
    print(f"初始解: 一级站{len(primary_stations)}个, "
          f"I型{L_I:.2f}km, II型{L_II:.2f}km, 总费用{C_total:.0f}元")
    
    # ===== 第五步：模拟退火优化 =====
    X0 = Solution(clusters, primary_stations, E_I, E_II, L_I, L_II, C_total)

if __name__ == "__main__":
